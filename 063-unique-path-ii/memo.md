# ステップ１

前回の問題の障害物があるバージョン。

前の問題のDP解をちょっと変えるだけで解けるはず。
最初にそこに障害物があるかどうかをチェックし、あるならそこにたどりつけるパスは無いので
dp[i][j] = 0
とすればよい。

コーナーケースとしてそもそも(0, 0)や(m-1, n-1)が障害物である場合も考えられるが、
その場合も特殊ケースとして処理せずにメインアルゴリズムで包括できる。
と思っていたが(0, 0)が障害物の場合はやはり場合分けは必要だった。

前回は全部1で埋めてから(1,1)からスタートするやり方をやったが、端に障害物があると端が全部1になると限らないので
今回はそれができないことにも注意する。

実装方法としては二重ループを回して左上から順に埋めていくか、メモ化再帰でやるかという違いもあるが、
そういえばＤＰにも「配るＤＰ」と「貰うＤＰ」の違いがあることを思い出した。

前回書いた
dp[i][j] = dp[i-1][j] + dp[i][j-1]
というやり方は貰うＤＰである。

一方で配るＤＰは(i, j)に来たときに次の候補地点に自分の値を渡していくやり方で具体的には

dp[i + 1][j] += dp[i][j]
dp[i][j + 1] += dp[i][j]

という風にやる。

この問題だとどっちでもそんなに分かりやすさは変わらないか、貰うＤＰ側のほうが分かりやすい気がするが
問題によっては配るＤＰのほうが分かりやすい場合もある。

メモ化再帰を以下のように書いてしまいWAの原因究明に時間がかかった。

```python
        def count_path(row: int, col: int) -> int:
            if path_count[row][col] is not None:
                return path_count[row][col]
            if not (0 <= row < height and 0 <= col < width):
                return 0
            if obstacleGrid[row][col] == OBSTACLE:
                return 0
            if row == 0 and col == 0:
                return 1 if obstacleGrid[0][0] != OBSTACLE else 0

            path_count[row][col] = count_path(row - 1, col) + count_path(row, col - 1)
            return path_count[row][col]
```

これは最初にrow, colが範囲外か確認しなければいけない。
そしてcol=-1とかになっていてもPythonは[-1]というアクセスができてしまうため、
範囲外参照になっているというエラーが起きずに計算はできてしまうがWAという結果になってしまっていた。

メモ化再帰の深さだが一番深い場合で右端からm-1回上に行く、n-1回左に行く場合なので高々m+n回の再帰深さになり、
今回はm, n <= 100なので高々200程度の再帰で済みまあ大丈夫そう。

first_obstacle_pos = obstacleGrid[0].index(1)
prev_num_paths = [1] * first_obstacle_pos + [0] * (n - first_obstacle_pos)

if 1 not in obstacleGrid[0]:

# ステップ３

２次元配列を使う方が分かりやすいとは思うが練習のために１次元配列のほうでやった。
forループの中で(0,0)を場合分けで処理するのも一個のためだけに毎回if分岐をチェックさせるのもなあという気持ち
になり、どちらもしっくりは来ないかもしれない。
再帰もよく考えると毎回(0,0)か（終了条件か）チェックするという意味で同じことをしているのだけど、
そっちはあまり違和感が無いので不思議だ。

改めて考えると配るＤＰにしておけば、こっちは(i, j)を見た段階では(i, j)の値が確定していることを前提とするため、
dp[i][j] = 1という初期値を入れた状態で(0, 0)からforループを回すのは全然自然なので、
そういう面では実は配るＤＰのほうがよかったかもしれない。
