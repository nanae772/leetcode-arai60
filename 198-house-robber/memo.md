# ステップ１

文脈を無視すると配列から隣り合わないよういくつかピックアップして
それらの合計が最大になるように取るといくらになるか？という問題

取り方は2^n通りあるのでそれらを全部試すとO(n * 2^n)かかり、
最大でn = 100になるこの問題ではとても現実的ではない。

- 0, 2, 4, ...
- 1, 3, 5, ...

のように奇数番目、偶数番目を全部取ってどちらか大きいほうが最大なのではないか
みたいな貪欲法は`[10, 1, 1, 10]`のようなケースでWAとなる。

配列の一番大きい奴を取ってその両端を消していくことを繰り返す貪欲法は
`[3, 5, 3]`のようなケースでWAとなる。

`dp[i] = 0..i番目だけを考えたときの最大値`
とする。dp[0]...dp[i-1]が既に分かっているときにdp[i]は

- i番目から取らない⇒dp[i-1]
- i番目から取る⇒dp[i-1]は(i-1)番目を既に取ってるかもしれないので2個前を参照してdp[i-2]+nums[i]

のどちらかになり`dp[i] = max(dp[i-1], dp[i-2] + nums[i])`と計算できる。
全体としてはO(n)の計算量でn = 100の最大ケースでも1ms以下で終わるだろう。

最初、以下のように書いてしまいWAとなった。
i = 1のときに本来はmax(max_money[0], nums[1])とならなければいけないが、
下のコードではmax_money[0]だけになっていた。

```python
class Solution:
    def rob(self, nums: list[int]) -> int:
        max_money = [0] * len(nums)
        max_money[0] = nums[0]
        for i in range(1, len(nums)):
            max_money[i] = max_money[i - 1]
            if i >= 2:
                max_money[i] = max(max_money[i], max_money[i - 2] + nums[i])
        return max_money[-1]
```

対策としてはmax_moneyを長さ(N+1)にして、`max_money[i]=[0, i)まで見たときの最大`とし、
`max_money[0] = 0`を入れて番兵みたいにする方法もあるが、
素直に0, 1の場合だけ初期化して2から始めるみたいな感じの方がいいかな。

解いたが全体的に2がマジックナンバーになってしまっているのがちょっと良くなさそう。

DPを使うときに直前と２個前の値しか使わないので配列を用意せずに２個の変数で解くこともできる。
各ステップでタプル代入を使って更新をかけているのでかなり分かりづらいかもしれない。
変数が多くなっても一時的に２個前の値を持つ変数を用意しておくほうがよいかな？
