# ステップ１

ローテートされたソート配列からtargetがあるindexをO(logn)で見つける。
ただし、存在しなければ-1を返す。

前回のFind Minimum in Rotated Sorted Arrayの考え方を延長すれば解けそう。
front=nums[0]として、[front以上], [front未満]に分ける。
target>=frontならtargetは[front以上]の中にあるはずなのでその中をさらに二分探索、
そうでなければ[front未満]の中を二分探索すればよい。

つまり、
1. [front以上], [front未満]の２つに分けるための二分探索をする: O(logn)
2. targetがどちらのレンジに属しているかを判定する: O(1)
3. どちらかのレンジからtargetを探すための二分探索: O(logn)

と２回二分探索を行えばよく時間計算量はO(logn)になる。
このときスライスなどを作ってしまうとO(n)になるのでそこは注意。
1の処理は関数化したほうが見通しが良くなりそう。

二分探索を１回で済ませる方法はあるだろうか？
[target以上], [target未満]のグループに分けられないかとか考えたけど
`nums = [4, 5, 6, 7, 0, 1, 2], target = 6`のようなケースで
`[4, 5], [6, 7], [0, 1, 2]`とバラバラになってしまうのでこれは上手くいかなさそう。
「target以上か」のTrue/Falseで考えるとFFTTFFFとなってしまいT/Fの境界が2つあるため、
この境界を二分探索で探そうとするとうまくいかない。
うーん、あるかもしれないがちょっと分からない。

とりあえず書いた。最終的に２つとも関数にして、1の関数はレンジを返すのではなく
前の問題でやったようにmin_indexを返してtargetを探すときに`[0, min_index), [min_index, len(nums))`
のどちらかを探させるというやり方にした。
二分探索が２つあるだけで急にややこしく感じるようになった。
もう少しきれいに書けるかもしれない。
