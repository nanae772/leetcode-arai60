# ステップ１

前回のHouser Robberは一直線上に家が並んでいたが、今回は円形に並んでいるので
最初の家と最後の家も隣接している。

最初にこの問題を見たときは最初に一個取るとアルファベットCのような形になって、
その中から２個目を取るとさらにCが２つになって…という感じに考えられるので
このCを区間で管理して区間に対するDPをやるのかなとか考えていて結構ややこしそうだと思った。

しかし改めて問題を読み直すと

- 最初の家から取ると決める⇒区間`[2, n-1)`に対して前回のhouse robberと同様に解ける
- 最初の家をスキップすると決める⇒区間`[1, n)`に対して前回のhouse robberと同様に解ける

なので、これらを各々実行し最後にどちらか大きい方を取ればいいのではないかと考えた。
とりあえずその方針で実装してみる。

コーナーケース(n <= 2)の場合をまとめて上手く処理できないか少し考えたが、
簡単にやる方法がちょっと思いつかなかったので素直に場合分けすることにした。

前回のようにまた2がマジックナンバーになってしまった。

自分は

- 先頭の家を取る場合/取らない場合

で場合分けをしていたがこちらの解法は

- 先頭の家を無視する場合/最後の家を無視する場合

と場合分けされており、こちらのほうがコードがかなりシンプルだった。2というマジックナンバーも出てこない。

一方でこの場合分けで本当に網羅漏れが起きていないかが自分にはちょっと論理的な説明が思いつかなかった。
「どこかの家を無視する」で網羅しようとしたら「`i(0<=i<n)`番目を無視する」でn通りの場合分けを
しなければいけないのではと考えてしまうけど、それがなぜi=0, n-1の場合だけで良くなるか。
何となく正しそうな気はするけどちょっと確証が持てない。
先頭を取る/取らないはP or (not P)という命題になっているのでこれは網羅漏れはないだろうと分かりやすい。

もう少し考える。

まず「先頭の家を取らない」は「先頭の家を無視する」と同値。

一方で、「先頭の家を取ると決めた場合」は最後の家を取ることができないので、
「先頭の家を取ると決める」⇒「最後の家を無視する」
が成り立つ、つまり「最後の家を無視する」の集合の方が大きいことになる。
よって「先頭の家を無視する」と「最後の家を無視する」の両方考えれば全てのケースを覆いつくせていることが分かる。

改めて集合で表すと

A: 先頭の家を取ると決めた場合の取り方の集合
B: 先頭の家を無視すると決めたときの取り方の集合
C: 最後の家を無視すると決めたときの取り方の集合

とすると

1. ~A = B (~AはAの補集合とする) 
2. A ⊂ C
3. A ∪ ~A = X (Xは全体集合)
4. 故に B ∪ C = X

ここまで考えてようやく網羅漏れは無いなと確信できた。
他の人はここまで論理的に考えなくても最初と最後を無視するだけで網羅漏れは無いと判断できるのかが気になった。
