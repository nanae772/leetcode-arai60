# ステップ１

N日間の株価が与えられるので、最も利益が高くなるタイミングで買って売ると最大でいくらになるか

買う日と売る日の全ての組合せを確かめる方法はO(N^2)となり、N=10^5となりえる入力では
とても1-2秒で終わるアルゴリズムではない。

前回も似たような問題があったと思うが、i日まで見たときの最小の株価min_priceを記憶しておいて
prices[i] - min_priceで最大利益を更新していけばよい。
ただしprices[i] < min_priceとなる場合はそれを新たにmin_priceにする。
これでO(N)になるので1秒あれば十分解ける速さになる。

というかもっとシンプルに考えると結局N日間全体を見て最小値で買って最大値で売ればいいのでは？と思ったけど、
それは最大値の後に最小値が来る場合などがダメなので結局前から順に見たときの最小値を持って
更新していく必要があった…

あまりDPという感じがしないがこれもDPなのか。
この他に別の解き方も特に思い浮かばないので次に進む。

# ステップ２

他の人の解法を見る。

https://github.com/akmhmgc/arai60/pull/32/files#r2420406592

`price < min_price`のときに場合分けをしたほうがよいのではないかという指摘。
自分はifのネストが増えるのが嫌でmax, minだけで簡潔させたが意図としてはif分岐の方が分かりやすいだろうか？

https://github.com/h1rosaka/arai60/pull/39/files#diff-0474f0ee7711182f0e97bb4047531dc4c65356748eafab139512400ac88c5c0bR10

min_priceをmath.infから始めるというのもあり得る。
個人的にはinfの型がfloatなので避けれるなら避けたいという気持ちもありつつ、便利なので使うこともある。
今回はnums[0]で初期化する方針にした。

https://github.com/Fuminiton/LeetCode/pull/37/files#diff-f9c9de67493d3f4cf662bc9fd74e8099695781e4a3f726dfc9dda5d330f541feR19

`min_price = prices[0]`と初期化しても`for price in prices[1:]:`とスライスしなくても動くという話。
自分もそのようにしたが、prices[0]から始まってるのにまた0から回すのは自然では無い気もする。
スライスを作るとその分コピーのコストが発生するのでそこをどうみるかというところか。
パフォーマンス面で特に問題が無い場合はスライスを作っちゃってもよさそう。

`for i in range(1, len(nums)):`とインデックスで回すのは１つの手でコピーを避けつつ1から始められる。
またGPTに教えてもらったが、itertools.isliceを使ってもコピーを発生させずに1から回せるようだ。

```python
        for price in itertools.islice(prices, 1, None):
            max_profit = max(max_profit, price - min_price)
            min_price = min(min_price, price)
```

そこまで行くと逆にちょっと複雑になりすぎて可読性が低くなってしまいそう。

# ステップ３

最終的にstep1と同じコードになった。
prices[1:]から始めることも考えたがこれはこれでlen(prices) = 1のときに範囲外参照っぽく見えてしまうのが気になった。
また0番目から回すとしてもmin_priceはprices[0]以上の十分大きな値なら何でもよくて、
その１つとしてinfを使うこともできるしprices[0]を使うこともできるという話でもあるので
別に今のままでも問題無いかと考えた。
結局このあたりは細かいので趣味の範囲だと思う。
