# ステップ１

荷物をdays日間で全て輸送できる船の容量の最小値を求める

capacityの容量でdays日間に輸送が完了するなら、明らかにcapacity+1の容量でも出来るという単調性がある。
よって「days日間で輸送できるか」のTrue/Falseは船の容量を動かしていくと
False, False, ..., False, True, True, ...
となっていくことが分かるのでこの境界を求めるのに二分探索が使える。

船の容量をcapacityに固定したときに、それでdays日間で輸送できるかどうかは
前から順に積んでいき、容量オーバーになるならそこで切って次の日に回すという単純なアルゴリズムで
判定でき、この計算量はO(n)になる。

二分探索の初期値は容量0は絶対にダメ、容量が全ての荷物の和なら1日で全部運べるので絶対出来ると分かる
(days=0というコーナーケースでない限り)ので、[0, sum(weights)]の範囲を探索する。
よって全体としての計算量はO(Nlog(sum(weights)))となり、最大ケースを考えると
N = 5*10^4, sum(weights) = 5 * 10^4 * 500 = 2.5 * 10^7
なのでざっくりNlog(sum(weights))≒10^6くらいでPythonでも1秒あれば間に合いそう。

一応コーナーケースとして

- days <= 0(どんな容量でも絶対に不可能)
- len(weights) = 0(どんな容量でもいけてしまう)

があり、これらに対しては例外を発生させるのがよさそうか。
前者はinf, 後者は0とか返すのも考え方によってはあるかもしれないが自然ではなさそう。

書いた。
`max_capacity_cant_ship = max(weights) - 1`にしておくと、can_shipの中の最初のチェックが
要らなくなるのと探索範囲が狭まりループの回数がやや減るがどちらのほうが分かりやすいだろうか。

あとcan_shipという関数名は名前だけだと軽量の判定に思ってしまいそうだが実際はO(n)かかるため、
より判定のための計算している名前にしたほうがいいだろうか。
