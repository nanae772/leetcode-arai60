# ステップ１

二分木の高さを求める

木と再帰関数の相性が良い（処理が分かりやすい）ため、まず再帰関数で書いてみて、
その後再帰を用いない処理に書き直してみることにする。

とりあえず書けた。

https://en.wikipedia.org/wiki/Tree_(abstract_data_type)

木の高さと深さの違いがよく分かってなかったが

- nodeの高さ=nodeから最も遠い葉までのパスの長さ
- 木の高さ=rootから最も遠い葉までのパスの長さ
- nodeの深さ=nodeからrootまでのパスの長さ

でパスの長さだから辺の本数を数えるのでこの問題とは厳密にはちょっと違った（この問題はパス上のノードの数を求めている）。
が、パスの長さ+1=ノードの数なので大きくは変わらない認識。

# ステップ２

ステップ１では書きやすさでNoneであることを終了条件にしていたが、普通に考えると「葉であるとき」を終了条件とした方が
直感的に分かりやすい気がする。最初に`root is None`の例外処理は必要になるが。

他の人のコードを見る。

https://github.com/akmhmgc/arai60/pull/17/files

幅優先探索であれば層ごとに+1していくだけでmax_depthが求められる。

再帰でも「上から今いる深さの情報を貰う」というやり方もある。
というか自分がstep1で書いたstackのほうは「上から配る」やり方になっていて、step1で書いた下から積み上げていく再帰のほうとは
違う形式になっているか…確かに。

- 下から上のstack解法(step2-stack-bottomup.py)
- 上から下のrecursion解法(step2-recursion-topdown.py)

の２つを書いてみた。下から上のstack解法は結構難しかった…再帰だと自動的に子から親へ値を伝播できるが、
それを実現するために別の構造体を作って親への参照を持たせるようにしてそれを実現した。

下から上の場合はnodeのheightを確定させていくのに対して上から下の場合はnodeのdepthを確定させていっているという違いが
これらの実装の違いによって分かった。

最初に「葉であることを終了条件にしたほうが直感的に分かりやすい」と書いたが、それはそれで条件分岐等でコードが煩雑になり
分かりやすくならない気がしたのでやっぱりNoneを終了条件にしたほうがいいかもと思った。

odaさんのstackで下から上をやる解法、かなりすっきりしている。
C/C++だとポインタを持てるのでそのポインタを通じて親への伝播が自動的に行える。
https://discord.com/channels/1084280443945353267/1227073733844406343/1236324993839792149

そしてPythonでもintの代わりに要素1のlist[int]を持つなどすれば同様のことができるようだ。
