# ステップ１

2次元マップの島の数を数える

やり方としては

1. 再帰関数を使って探索する深さ優先探索
2. スタックを使って探索する深さ優先探索
3. キューを使って探索する幅優先探索
4. UnionFindで島をくっつけていき最後に連結成分がいくつあるか数える

というやり方がある。
今回は2,4のやり方で解いてみることにする。

とりあえず書けたが、UnionFindってこんなのだったかな…？自信が無い。
一応経路圧縮とサイズの小さい方をサイズの大きい方にくっつけるをやって各操作のならし計算量がO(α(n))になるはず。
（αはアッカーマン関数の逆関数とかでnがめちゃくちゃ大きくなってもほぼ増えないとかだった記憶）

# ステップ２

どっちのやり方にしろ「盤外に出てないか」「水の上か」などは繰り返し出てくる判定なので関数化しておいたほうがよさそう。

UnionFindのほうはだいぶいろいろサボっていて、人に読ませるコードではない。
各森のルートのparentに`-(その森のサイズ)`が入ってるとかも説明が無いと分から無さそう。
あと最後にUnionFindの連結成分を数える方法、もうちょっと良い方法無いかな。

最初にn個のバラバラの連結成分があって、マージが起こったときに１個ずつ連結成分が減っていくので
そのあたりの処理を組み込めば最後にO(1)で連結成分の個数を求められそう。

3重ループになってしまっている部分は関数化したほうがよさそう。

is_visitedとの整合性も取れるしvisit_connected_islandsとかでよさそう。

dfsのほうのアルゴリズムがスタックからポップしたタイミングでis_visitedをTrueにしているけど、
そうすると同じ地点が２回以上スタックに入ることがあって二重に処理されているか。
スタックに積んだタイミングでis_visitedをTrueにしたほうがよかったかもしれない、ちょっと違和感あるけど…

そういえば２重ループのネストを減らす工夫としてはitertools.productを使うことができる
https://docs.python.org/ja/3.13/library/itertools.html#itertools.product
