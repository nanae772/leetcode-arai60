# ステップ１

ソート済み数値配列をheight-balanced binary search treeに変換する

height-balancedであるとは、各ノードについて左の部分木と右の部分木の高さが高々１しか変わらないことである、とのこと。

何となくだが真ん中の値を取って、左右のノードがなるべく同じ個数になるように構築することを再帰的に繰り返せば
height-balancedになりそうなのでその方針で実装してみる。

実装した。区間は[begin, end)(beginを含みendを含まない半開区間)で管理するようにした。
名前はleft, rightもよく使われるが今回は二分木の意味でのleft, rightと混同しそうだったので
begin, endにした。

各ステップで区間が半分ずつになっていくので再帰の深さも高々logN程度で、
N=10^4であれば20もいかないくらいなのでこれくらいであれば再帰を使っても問題無さそう。

これでなぜheight-balancedになるかを考えてみると、持ってる区間の長さL(=end - begin)について

- Lが奇数なら左右で同じ区間の長さL/2で分けられる。区間の長さが同じであれば、作られる部分木の高さは等しくなる。
- Lが偶数ならどちらかの区間の長さが１だけ変わるので、左右で作られる部分木の高さも高々１しか変わらない。

という考え方であっているだろうか。

indexではなくsliceを渡す方法。Pythonでこれをやると再帰呼び出しごとに区間の長さ分スライスのコピーが発生して
その分の計算量がかかるのでおおよそ
`N/2*2 + N/4*4 + N/8*8 + ... = N * logN`
になりそう。
計算量の面ではややindexを渡す方法のほうが優れているが、sliceを渡す方は引数が１つで済むので
そちらのほうが複雑さは減って分かりやすい面もあるかもしれないと思った。
